# 同账号多端消息与交付顺序

[首页](../README.md) · [更新日志](../CHANGELOG.md) · [WebSocket](websocket-protocol.md)

浏览器与桌面可以同时登录，同类新登录替换旧会话。后端分别按本人和接收者视角推送；允许登录不等于消息天然完成多端同步，以下合并规则由客户端落实。

## 客户端规则

- type2/type5 通过 `sendUserId` 识别本人回显，不增加自己的未读，不把自己作为联系人。
- HTTP、WS 和历史按 `messageId` 去重，交付先后不同也只显示一条气泡及一致摘要。
- type6 更新已有附件，保留 `messageType=5`，合并最终原名/大小/类型/完成状态。旧服务器缺少元数据时保留已有值，非法控制帧不能修改普通文字。
- 本人 type2 按账号、客户端键、会话、联系人和内容确认待发，兼容服务端 HTML 转义。确认后立即清理匹配的待发与旧草稿。
- HTTP 迟到或丢失不得复活已确认待发，不覆盖用户后来输入的新草稿；尚未确认的在线 503 仍正常报错。
- 私有备注只在本人设备同步，AI 私有会话也不向无关账号传播。

## 真实运行证据

| 场景 | 已确认结果 |
|---|---|
| 固定 Web + Electron `a5f96bd` + 隔离后端 | 并行登录、双向私聊、Web 附件、桌面 HEVC、双向 AI 共六组通过 |
| 本人后台会话 | 无新增未读，每端只显示一条消息 |
| HEVC 最终元数据 | 输入 4589 字节，转码后 3169 字节；服务器下载、Web 卡片、SQLite 与媒体窗一致，延迟/换会话后不回退 |
| WS 已确认而 HTTP 回包被丢弃 | IndexedDB 可用/不可用两组均为服务端一行、UI 一条、无待发或草稿复活、零 pageerror |

测试 HTTP 确实到达服务器，未用模拟成功响应代替交付；邮件/AI 使用本机协议兼容提供方。运行后端 JAR SHA-256 为 `41b74834b636cdcfe0e040c0faf58bd86b2435f59a7ad58fdc8dad6dc73c284e`。

多端元数据阶段针对性 102 项、待发确认阶段相关 103 项通过；它们是阶段子集，不能相加为最终总数。统一功能基线为 Web `845c6d9` 的 373 项，最后的入口验收使用另一个明确快照，见 [总矩阵](feature-parity-audit.md)。

原始结果为私有目录 `D:/environment/WeTalkParityQA/20261004/` 中的 `desktop-mirror-results.json`、`acknowledgement-results.json`；精确消息编号与清理记录在联合工作区 `audit/multi-device-runtime.md`。凭据不提交到 Git。
