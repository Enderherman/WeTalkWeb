# 同账号多端消息同步

2026-10-04 核验发现：允许同时登录浏览器和桌面会话，并不自动保证本人的私聊消息同步到另一端。后端原实现只向接收者推送，文件完成事件也缺少最终元数据；本轮按三端协议补齐。

## 客户端规则

- 本人发出的 type2/type5 回显按 `sendUserId` 识别；不增加自己的未读，也不把自己当成联系人。
- WebSocket 回显与 HTTP 返回按 `messageId` 去重，无论哪个先到都只显示一条，并使用一致的会话预览。
- type6 只更新已有文件消息，保留原 `messageType=5`；合并最终 `fileName/fileSize/fileType`、上传完成状态和进度，便于转码后显示实际大小。
- 兼容旧服务器仅含 messageId/status 的 type6，不把缺失字段清空；非法控制帧不能改变普通文字消息。
- 本人 type2 回显按账号、客户端键、会话、联系人及内容匹配待发尝试；收到确认立即清理本机待发/原草稿。兼容服务端已有的 HTML 转义文本。
- HTTP 回包晚到或丢失时，已由 WebSocket 确认的消息不会重新出现为待发/失败，不会覆盖用户随后编辑的新草稿。正常未确认的在线服务错误仍给出通用错误和重试行为。
- 后端本人/接收者视角扇出已通过真实 Web/Electron 联调；不同客户端之间沿用当前会话身份，私有备注不泄漏到对方。

验证：新增四个交付顺序/元数据/类型保护案例，其中三项先复现失败；修复后 chatStore + 认证流程 **102 项**、独立类型检查、生产构建通过。

待发确认另新增身份/内容匹配与两种缓存可用性回归，两个组件场景先复现失败；修复后相关 **103 项**通过，包含 HTTP 丢失、合法在线 503 仍报告、保留未确认草稿。该阶段全量曾通过 361 项，随后补充的在线 503 用例通过；最终统一计数见 README/总验收表。

## 真实运行结果

独立本机后端与 Electron `a5f96bd`、Web 固定生产快照完成六组检查：并行登录、双向私聊、Web 附件、桌面 HEVC 转码、双向 AI 提问。本人消息在另一端后台会话不增加未读，各端只保留一条气泡。HEVC 原文件 4589 字节，实际转码后 3169 字节；服务端下载、Web 文件卡片、桌面 SQLite 和媒体窗均使用最终大小，延时和切换会话后不回退。无关账号没有收到私有 AI 提问。

另外两组真实 HTTP/WS 交付乱序测试分别在 IndexedDB 可用和不可用时，让请求实际到达服务器、WS 回显已到、随后丢弃 HTTP 回包；服务端仅一行，UI 仅一条，待发/旧草稿不重新出现，页面异常为零。测试只使用本机隔离账号和协议兼容 AI fixture。

精确版本、消息编号和资源清理见工作区 `audit/multi-device-runtime.md`；原始结果在私有目录 `D:/environment/WeTalkParityQA/20261004/desktop-mirror-results.json` 与 `acknowledgement-results.json`，不随仓库提交账号凭据。
