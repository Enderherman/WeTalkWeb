# 登录会话与异步请求归属

2026-10-04 的延迟响应回归确认：旧聊天组件卸载后，A 的资料读取/保存结果仍可能与当前 B 的 session 合并，导致 B 的邮箱、昵称和 admin 显示字段变成 A；旧请求的 901/503 也可能清理或跳转新会话。同一账号用 Cookie 重新登录时 token 仍为空，单靠用户 ID / token 比较不能区分两次登录。

修复为每次登录替换/退出递增独立的 session generation，并与用户 ID/token 共同组成请求上下文。资料更新使用同一会话内的受限更新方法，不递增 generation，所以不会误取消同时进行的历史/设备等请求。

- HTTP 在调用时捕获上下文、发送前检查归属、响应/异常和 Blob 解析后再次检查。陈旧请求按取消返回，不广播新会话的认证/服务错误；发送前已换账号的请求不会改用新账号凭据发送。
- ChatHome 的资料读取/保存同时检查组件仍存在、请求序号和会话归属，并校验返回 profile.userId；切换会话清除旧资料展示。退出和改密的迟到完成也不会清除新登录。
- 当前会话正常 901/500 行为保留；正常资料刷新不使并行请求失效。Axios 主动取消与 beforeunload/pagehide/pageshow 处理继续生效。

验证：新增7个问题回归在修改前全部失败；修复及边界用例后相关6文件99项通过，全量47文件347项通过，类型检查和生产构建通过。测试覆盖换账号、同用户新登录、组件卸载、迟到退出、迟到901/503/Blob、发送前账号变化、正常901与并行资料刷新。
