# 登录会话与异步请求归属

[首页](../README.md) · [更新日志](../CHANGELOG.md) · [卸载生命周期](webkit-navigation-lifecycle.md)

请求必须属于发起时的登录会话。用户编号相同并不代表还是同一次登录：Web Cookie 会话没有可供页面比较的 token，因此认证状态用独立 `session generation` 区分每次登录替换和退出。

## 当前规则

- HTTP 调用时捕获用户 ID/token/会话代次，发送前、响应或异常、Blob 解析后分别检查归属。发送前已换账号的请求不会改用新账号凭据发送。
- 陈旧请求按取消处理，不更新新账号资料，不派发新会话的 901/服务错误导航。
- 资料读取/保存同时检查组件仍存在、请求序号、会话归属和返回的 `profile.userId`；切号清除旧资料展示。
- 迟到的退出/改密完成不能清除新登录。正常资料刷新是同会话受限更新，不递增代次，不取消并行历史或设备请求。
- 当前会话真实 901/5xx、主动取消和页面卸载各自保留相应处理，不通过忽略全部错误实现隔离。
