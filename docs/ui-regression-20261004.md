# 2026-10-04 本机真实浏览器复核

环境：独立 MySQL/Redis/Spring 后端与本机 Vite 同源代理；测试账号、邮件收件器和 AI SSE 提供方均为隔离测试数据。浏览器为真实 Chromium 引擎的自动化运行，非 iOS/Android 实体设备。

## 已验证的用户流程

- 实际登录表单、HttpOnly Cookie、两个独立账号的 WebSocket INIT。
- 双账号文字发送、实时接收、发送者已读回执和刷新后的历史恢复。
- 私有好友备注事件只到本人，会话/刷新恢复使用备注，对方看不到。
- 会话置顶、移除、恢复；390/768/1280px 下无横向溢出且输入框在视口内。
- 真实 SSE 超过 500 字回复完整持久化、一次回复仅一条；停止生成保存部分文字与终止状态。
- 管理员通过页面新增版本、灰度发布、双账号可见性、撤回和删除。
- 用户、群聊、系统设置、靓号、版本发布五个管理页面在 390px 下页面宽度均为 390px。
- 登录失败后保持登录页、显示错误；实际计算错误提示背景为 `rgb(255, 243, 241)`。

## 本轮实际发现并修复

1. 历史较多、版本提示和会话操作同时出现时，聊天主区被内容撑高，输入框落到屏幕外。根网格及主区最小高度修复后，历史在内部滚动。
2. 管理导航禁止收缩，将手机标题挤成竖排并横向溢出。现在支持换行和窄屏纵向排列。
3. 版本发布边框使用不存在的颜色变量，登录错误背景包含无效 CSS，部分表头/只读控件和下载设置引用未定义表面色；已统一到已有主题变量。
4. 用户管理卡片操作区的 `100%` 宽度再叠加左外边距，造成 390px 页面扩到 411px；现在扣除外边距并允许按钮换行。重新确认目标路由与管理页标题后，五个真实管理页面均为 390px、无溢出。
5. WebKit 点击账号菜单时可先产生目标为空的失焦事件，旧逻辑在 click 前删除菜单，导致个人设置打不开。现在分别处理外部指针点击和有明确目标的键盘焦点离开，不会吞掉菜单操作；窗口失焦仍关闭菜单，卸载时清理监听。
