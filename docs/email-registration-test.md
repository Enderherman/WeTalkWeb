# 邮箱验证码注册与验证范围

[首页](../README.md) · [更新日志](../CHANGELOG.md) · [REST 契约](api-inventory.md)

## 用户流程

注册页填写昵称、邮箱、密码与确认密码，解答图片验证码后请求邮箱码，再使用六位邮箱码创建账号。发送成功进入冷却，冷却到期可重发；失败显示可重试错误。邮箱码有效期为 10 分钟，已消费或过期的码不能再次注册。

接口顺序为 `/account/checkCode`、`/account/registerEmailCode`、`/account/register`。邮箱码请求带 `email/checkCodeKey/checkCode`，注册带 `email/password/nickName/emailCode`。验证码与口令不写入仓库、日志或前端环境变量。

## 当前证据

| 范围 | 结果与限制 |
|---|---|
| Web 表单 | 发送冷却、重发、失败提示和重试有自动化覆盖，纳入最终 373 项功能基线 |
| 2026-10-04 隔离后端 | 本机 SMTP 收件器与真实 HTTP 验证注册及验证码错误/过期/已消费；不使用外部邮箱或真实用户 |
| 2026-09-28 外部邮件历史 | NAS 真实图片验证码路径调用邮件接口成功；用户确认收件，随后只读检查时验证码已过期，未用该码创建真实账号 |

本机邮件协议兼容测试证明应用链路，不证明外部 SMTP 当前连通或收件及时。外部提供方、生产 Cookie/HTTPS 和真实邮箱完成注册仍需在正式环境单独验收。旧诊断夹具的问题和部署过程已归并至 [更新日志](../CHANGELOG.md)，不作为当前产品行为。

## 复验要点

使用专用测试邮箱，按页面正常解答图片验证码；记录发送结果、收件时间、消费/过期行为和注册后的登录，不记录验证码明文。检查成功和失败后的按钮状态，清理已授权的测试数据。无需重启共享数据库或向 Redis 写入绕过验证码的长期数据。
